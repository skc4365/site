# 텍스트 분할 실습

긴 문서를 검색과 모델 입력에 적합한 **청크(Chunk)** 로 분리하는 텍스트 분할. 검색 품질, 문맥 보존, 처리 비용을 좌우하는 RAG 핵심 단계.

## 핵심 개념

| 항목 | 핵심 |
| --- | --- |
| `chunk_size` | 청크의 목표 최대 크기 |
| `chunk_overlap` | 인접 청크의 중복 범위 |
| 구분자 | 문단·문장·공백 등 분할 기준 |
| 길이 함수 | 문자 수 또는 토큰 수 계산 |
| 메타데이터 | 출처·제목·위치 등 검색 근거 |

- 작은 청크: 검색 정밀도 증가, 문맥 감소, 청크 수 증가
- 큰 청크: 문맥 증가, 검색 잡음과 토큰 비용 증가
- Overlap 증가: 경계 문맥 보존, 중복 저장량 증가
- 권장 기준: 실제 질문과 검색 결과를 이용한 반복 평가

> **실습 환경**
>
> Python 3.12, LangChain 1.x 기준. HTML URL 분할의 보안 패치가 포함된 `langchain-text-splitters>=1.1.2` 권장.

<details markdown="1">
<summary>공통 패키지 설치</summary>

```bash
pip install -U "langchain-text-splitters>=1.1.2" tiktoken beautifulsoup4
```

SemanticChunker 실습용 추가 패키지:

```bash
pip install -U langchain-experimental langchain-openai
```

</details>

## 1. CharacterTextSplitter

지정한 **단일 구분자**로 분할하는 가장 단순한 방식.

- 기준: 기본 구분자 `\n\n`, 기본 길이 단위 문자 수
- 적합: 문단 구분이 일정한 텍스트
- 주의: 구분자 사이의 텍스트가 매우 길면 `chunk_size` 초과 가능
- 반환: `split_text()`는 문자열, `create_documents()`는 `Document`

<details markdown="1">
<summary>예제 코드: 문단 기준 분할</summary>

```python
from langchain_text_splitters import CharacterTextSplitter

text = """문서 로더는 원본 데이터를 Document로 변환합니다.
각 Document는 본문과 메타데이터로 구성됩니다.

텍스트 분할기는 긴 문서를 작은 청크로 나눕니다.
청크 크기와 중복 범위는 검색 품질에 영향을 줍니다.

분할된 청크는 임베딩을 거쳐 벡터 저장소에 저장됩니다.
검색기는 질문과 가까운 청크를 반환합니다."""

splitter = CharacterTextSplitter(
    separator="\n\n",
    chunk_size=80,
    chunk_overlap=10,
    length_function=len,
    is_separator_regex=False,
)

chunks = splitter.split_text(text)

for index, chunk in enumerate(chunks, start=1):
    print(f"[청크 {index}] 길이={len(chunk)}")
    print(chunk)
```

`Document`와 메타데이터 생성:

```python
documents = splitter.create_documents(
    texts=[text],
    metadatas=[{"source": "text-splitting-guide"}],
)

print(documents[0].page_content)
print(documents[0].metadata)
```

</details>

## 2. RecursiveCharacterTextSplitter

여러 구분자를 순서대로 적용하는 범용 기본 분할기.

- 기본 순서: 문단 → 줄 → 공백 → 문자
- 기본 구분자: `["\n\n", "\n", " ", ""]`
- 적합: 일반 문서, 형식이 일정하지 않은 텍스트
- 장점: 가능한 한 문단과 단어 구조 유지

<details markdown="1">
<summary>예제 코드: 일반 문서 재귀 분할</summary>

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text = """# 텍스트 분할

텍스트 분할은 긴 문서를 검색 가능한 청크로 나누는 과정입니다.
적절한 청크 크기는 질문 유형과 문서 구조에 따라 달라집니다.

## 청크 중복

청크 중복은 경계에서 잘리는 문맥을 보존합니다.
중복이 너무 크면 저장 공간과 검색 결과의 반복이 증가합니다."""

splitter = RecursiveCharacterTextSplitter(
    chunk_size=90,
    chunk_overlap=15,
    separators=["\n\n", "\n", ". ", " ", ""],
    length_function=len,
    add_start_index=True,
)

documents = splitter.create_documents(
    [text],
    metadatas=[{"source": "guide.md"}],
)

for document in documents:
    print(document.metadata)
    print(document.page_content)
```

</details>

## 3. 토크나이저, TokenTextSplitter

모델의 토크나이저 기준으로 청크 크기를 계산하는 방식.

- 적합: 모델 Context Window와 입력 비용 관리
- `TokenTextSplitter`: 토큰 수의 엄격한 상한 관리
- `from_tiktoken_encoder()`: 문자 구조와 토큰 계산의 결합
- 주의: 한국어 문자의 토큰 경계 손상 방지를 위해 재귀 방식 우선 검토

<details markdown="1">
<summary>예제 코드: 토큰 수 확인과 TokenTextSplitter</summary>

```python
import tiktoken
from langchain_text_splitters import (
    RecursiveCharacterTextSplitter,
    TokenTextSplitter,
)

text = (
    "텍스트 분할은 모델의 입력 한도를 관리하고 "
    "검색에 적합한 문맥 단위를 만드는 과정입니다. "
) * 10

encoding = tiktoken.get_encoding("cl100k_base")
token_count = len(encoding.encode(text))
print(f"전체 토큰 수: {token_count}")

token_splitter = TokenTextSplitter(
    encoding_name="cl100k_base",
    chunk_size=40,
    chunk_overlap=5,
)
token_chunks = token_splitter.split_text(text)

for index, chunk in enumerate(token_chunks, start=1):
    size = len(encoding.encode(chunk))
    print(f"[TokenTextSplitter {index}] 토큰={size}")
```

한국어 등 다중 토큰 문자에 유리한 재귀 분할:

```python
safe_splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
    encoding_name="cl100k_base",
    chunk_size=40,
    chunk_overlap=5,
)
safe_chunks = safe_splitter.split_text(text)

for index, chunk in enumerate(safe_chunks, start=1):
    print(index, len(encoding.encode(chunk)), repr(chunk))
```

</details>

## 4. SemanticChunker

인접 문장의 임베딩 거리를 기준으로 **의미가 바뀌는 지점**을 탐색하는 분할기.

- 기준: 문장 간 의미 차이
- 적합: 주제 전환이 뚜렷한 보고서·기사
- 장점: 고정 길이보다 자연스러운 의미 단위
- 비용: 임베딩 API 호출, 처리 시간 증가
- 주요 기준: `percentile`, `standard_deviation`, `interquartile`, `gradient`

<details markdown="1">
<summary>예제 코드: 의미 변화 기준 분할</summary>

```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

text = """
RAG는 외부 문서를 검색해 모델의 답변을 보강합니다.
검색 품질은 문서 분할과 임베딩 품질의 영향을 받습니다.

태양광 발전은 햇빛을 전기에너지로 변환합니다.
발전량은 일사량과 패널 효율에 따라 달라집니다.

예지 정비는 센서 데이터로 고장 가능성을 예측합니다.
진동과 온도 변화는 설비 이상 탐지의 주요 신호입니다.
"""

splitter = SemanticChunker(
    embeddings=OpenAIEmbeddings(model="text-embedding-3-small"),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=80,
)

documents = splitter.create_documents([text])

for index, document in enumerate(documents, start=1):
    print(f"[의미 청크 {index}]")
    print(document.page_content)
```

실행 조건: `OPENAI_API_KEY` 환경변수. 운영 환경에서는 임베딩 비용과 재처리 정책 검토.

</details>

## 5. 코드 분할하기

언어별 클래스·함수·제어문 경계를 우선하는 구조 기반 분할.

- 기준: `Language` 열거형의 언어별 구분자
- 적합: 소스 코드 검색, 코드 RAG, 저장소 분석
- 장점: 함수와 클래스의 의미 단위 보존
- 지원 예: Python, Java, JavaScript, TypeScript, Go, Rust, C/C++, C#

<details markdown="1">
<summary>예제 코드: Python 함수와 클래스 기준 분할</summary>

```python
from langchain_text_splitters import (
    Language,
    RecursiveCharacterTextSplitter,
)

python_code = """
class TemperatureSensor:
    def __init__(self, sensor_id):
        self.sensor_id = sensor_id

    def read(self):
        return 23.5


def is_overheated(temperature, limit=80):
    return temperature >= limit


def create_alert(sensor_id, temperature):
    return {
        "sensor_id": sensor_id,
        "temperature": temperature,
        "level": "critical",
    }
"""

splitter = RecursiveCharacterTextSplitter.from_language(
    language=Language.PYTHON,
    chunk_size=140,
    chunk_overlap=20,
    add_start_index=True,
)

documents = splitter.create_documents(
    [python_code],
    metadatas=[{"source": "sensor.py", "language": "python"}],
)

for index, document in enumerate(documents, start=1):
    print(f"[코드 청크 {index}] {document.metadata}")
    print(document.page_content)
```

언어별 구분자 확인:

```python
separators = RecursiveCharacterTextSplitter.get_separators_for_language(
    Language.PYTHON
)
print(separators)
```

</details>

## 6. MarkdownHeaderTextSplitter

Markdown 제목 계층을 기준으로 분할하고 제목 정보를 메타데이터로 보존하는 방식.

- 기준: `#`, `##`, `###` 등 지정한 헤더
- 적합: README, 기술 문서, 매뉴얼
- 기본값: 결과 본문에서 헤더 제거
- 옵션: `strip_headers=False`로 헤더 유지
- 참고: 일반 `TextSplitter` 상속 구조가 아닌 전용 분할기

<details markdown="1">
<summary>예제 코드: Markdown 제목 계층 보존</summary>

```python
from langchain_text_splitters import MarkdownHeaderTextSplitter

markdown = """# 설비 매뉴얼

설비 운영을 위한 기본 문서

## 기동 절차

전원 상태를 확인합니다.
시작 버튼을 누릅니다.

### 안전 확인

작업 반경에 사람이 없는지 확인합니다.

## 정지 절차

부하를 제거한 뒤 정지 버튼을 누릅니다.
"""

headers = [
    ("#", "chapter"),
    ("##", "section"),
    ("###", "topic"),
]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers,
    strip_headers=False,
)
documents = splitter.split_text(markdown)

for document in documents:
    print(document.metadata)
    print(document.page_content)
```

헤더 단위 결과가 너무 긴 경우의 2단계 분할:

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

size_splitter = RecursiveCharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=15,
)
final_documents = size_splitter.split_documents(documents)
```

</details>

## 7. HTMLHeaderTextSplitter

HTML의 제목 태그를 기준으로 계층을 추출하고 메타데이터로 보존하는 방식.

- 기준: `h1`, `h2`, `h3` 등 지정 태그
- 적합: 구조화된 웹 문서, 도움말, 제품 문서
- 입력: HTML 문자열 또는 로컬 파일
- URL 처리: 콘텐츠를 별도로 가져온 뒤 `split_text()`에 전달

<details markdown="1">
<summary>예제 코드: HTML 제목 구조 기준 분할</summary>

```python
from langchain_text_splitters import HTMLHeaderTextSplitter

html = """
<html>
  <body>
    <h1>설비 점검 가이드</h1>
    <p>정기 점검의 기본 절차</p>

    <h2>일일 점검</h2>
    <p>온도와 진동 값을 확인합니다.</p>

    <h3>온도 기준</h3>
    <p>정상 범위는 20~70도입니다.</p>

    <h2>월간 점검</h2>
    <p>필터와 윤활 상태를 확인합니다.</p>
  </body>
</html>
"""

headers = [
    ("h1", "chapter"),
    ("h2", "section"),
    ("h3", "topic"),
]

splitter = HTMLHeaderTextSplitter(
    headers_to_split_on=headers,
    return_each_element=False,
)
documents = splitter.split_text(html)

for document in documents:
    print(document.metadata)
    print(document.page_content)
```

큰 HTML 섹션의 추가 분할:

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

size_splitter = RecursiveCharacterTextSplitter(
    chunk_size=150,
    chunk_overlap=20,
)
final_documents = size_splitter.split_documents(documents)
```

</details>

## 8. RecursiveJsonSplitter

중첩 JSON의 계층을 가능한 한 유지하며 크기 기준으로 재귀 분할하는 방식.

- 기준: JSON 객체의 키·값 구조와 문자 수
- 적합: API 응답, 설정 파일, 로그, 중첩 데이터
- `split_json()`: Python 딕셔너리 목록
- `split_text()`: JSON 문자열 목록
- `create_documents()`: LangChain `Document` 목록
- 주의: 매우 긴 단일 문자열 값은 추가 텍스트 분할 필요

<details markdown="1">
<summary>예제 코드: 중첩 JSON 구조 보존</summary>

```python
from langchain_text_splitters import RecursiveJsonSplitter

data = {
    "factory": {
        "name": "서울 1공장",
        "lines": [
            {
                "line_id": "A",
                "machines": [
                    {"id": "A-01", "status": "running", "temperature": 42.1},
                    {"id": "A-02", "status": "warning", "temperature": 78.4},
                ],
            },
            {
                "line_id": "B",
                "machines": [
                    {"id": "B-01", "status": "stopped", "temperature": 25.0}
                ],
            },
        ],
    }
}

splitter = RecursiveJsonSplitter(
    max_chunk_size=180,
    min_chunk_size=80,
)

json_chunks = splitter.split_json(
    json_data=data,
    convert_lists=True,
)

for index, chunk in enumerate(json_chunks, start=1):
    print(f"[JSON 청크 {index}]")
    print(chunk)
```

`Document` 생성:

```python
documents = splitter.create_documents(
    texts=[data],
    metadatas=[{"source": "factory-status.json"}],
    convert_lists=True,
)

for document in documents:
    print(document.metadata)
    print(document.page_content)
```

</details>

## 분할기 선택 가이드

| 데이터 유형 | 권장 분할기 | 선택 이유 |
| --- | --- | --- |
| 구분자가 일정한 텍스트 | `CharacterTextSplitter` | 단순하고 예측 가능한 분할 |
| 일반 문서 | `RecursiveCharacterTextSplitter` | 문단과 단어 구조 우선 보존 |
| 모델 입력 한도 관리 | `TokenTextSplitter` | 토큰 수 기준의 크기 제어 |
| 주제 전환이 뚜렷한 문서 | `SemanticChunker` | 의미 변화 기준 분할 |
| 프로그램 소스 | 언어별 코드 분할 | 함수·클래스 구조 보존 |
| Markdown | `MarkdownHeaderTextSplitter` | 제목 계층을 메타데이터로 유지 |
| HTML | `HTMLHeaderTextSplitter` | HTML 제목 구조 유지 |
| 중첩 JSON | `RecursiveJsonSplitter` | 키·값 계층 보존 |

## 최종 점검

- 정답 문맥의 단일 청크 포함 여부
- 청크별 출처와 제목 메타데이터
- 중복 청크의 검색 결과 과점유 여부
- 모델 토크나이저 기준 입력 한도
- 실제 질문 세트를 이용한 검색 정확도
