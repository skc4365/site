# 메모리(Memory) — 대화 상태와 사용자 정보를 필요한 범위에 저장하는 구조

## 개념

**메모리**는 이전 상호작용의 상태나 정보를 저장하고 이후 실행에서 다시 사용하는 기능입니다.

## 언제 사용하는가

- 같은 대화에서 이전 질문을 이어갈 때
- 사용자 선호를 여러 대화에서 재사용할 때
- 중단된 Agent 실행을 복원할 때

## 아키텍처

```text
Short-term: thread_id → Checkpointer → 대화 State
Long-term:  user namespace → Store → 선호·사실
```

## 핵심 원리

| 구분 | 범위 | 저장 대상 |
|---|---|---|
| 단기 메모리 | 한 thread | 메시지와 현재 작업 상태 |
| 장기 메모리 | 여러 thread | 사용자 선호와 지속 정보 |

대화 전체를 무제한으로 모델에 넣으면 비용과 잡음이 증가합니다. 최근 메시지 유지, 오래된 내용 요약, 필요한 사실만 저장하는 정책이 필요합니다.

## 바로 실행하는 코드

```bash
pip install -U langchain langchain-openai langgraph
```

`OPENAI_API_KEY` 환경 변수를 설정한 뒤 실행합니다.

```python
from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-4.1-mini",
    tools=[],
    checkpointer=InMemorySaver(),
)
config = {"configurable": {"thread_id": "student-01"}}

agent.invoke({"messages": [{"role": "user", "content": "내 이름은 민수야."}]}, config)
result = agent.invoke({"messages": [{"role": "user", "content": "내 이름은?"}]}, config)
print(result["messages"][-1].content)
```

## 요점 정리

1. 단기 메모리는 thread, 장기 메모리는 사용자 범위입니다.
2. `thread_id`와 사용자 ID는 같은 개념이 아닙니다.
3. Checkpointer는 그래프 State를 저장합니다.
4. 운영 환경에서는 지속 저장소와 사용자 격리가 필요합니다.
5. 보존 기간과 삭제 정책을 먼저 정합니다.
