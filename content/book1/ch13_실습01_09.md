# Retriever 실습

질문을 입력받아 관련 `Document` 목록을 반환하는 **검색 인터페이스**. 검색 방식과 생성 모델 사이의 표준 연결 계층.

## 핵심 구조

```text
질문(Query) → Retriever → 검색·필터·압축·재정렬 → list[Document]
```

| 구분 | 핵심 |
| --- | --- |
| VectorStore | 임베딩과 원문 저장, 벡터 유사도 검색 |
| Retriever | 질문을 받아 관련 문서 반환 |
| Compressor | 검색 문서의 불필요한 부분 제거·재정렬 |
| `k` | 최종 반환 문서 수 |
| `fetch_k` | 재정렬 전 후보 문서 수 |
| Metadata Filter | 기간·유형·권한 기반 검색 범위 제한 |

- 공통 호출: `retriever.invoke(query)`
- 공통 반환: `list[Document]`
- 검색 평가: Recall@k, Precision@k, MRR, nDCG
- 검색 품질과 답변 품질의 분리 평가
- 운영 환경의 권한 필터와 출처 메타데이터 필수

```python
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import ChatOpenAI, OpenAIEmbeddings

documents = [
    Document(
        page_content="프레스 설비의 유압은 매일 점검하고 누유 여부를 기록합니다.",
        metadata={"document_id": "M-001", "equipment": "press", "year": 2025, "priority": 3},
    ),
    Document(
        page_content="모터 진동 증가 시 베어링 마모와 축 정렬 상태를 점검합니다.",
        metadata={"document_id": "M-002", "equipment": "motor", "year": 2024, "priority": 2},
    ),
    Document(
        page_content="컨베이어 비상 정지 후 전원을 차단하고 이물질을 제거합니다.",
        metadata={"document_id": "M-003", "equipment": "conveyor", "year": 2025, "priority": 3},
    ),
    Document(
        page_content="윤활유는 6개월 또는 2,000시간마다 교체합니다.",
        metadata={"document_id": "M-004", "equipment": "motor", "year": 2023, "priority": 1},
    ),
]

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
llm = ChatOpenAI(model="gpt-5.4-mini")
vector_store = InMemoryVectorStore.from_documents(documents, embeddings)
```

> 아래 예제는 공통 예제의 `documents`, `embeddings`, `llm`, `vector_store` 사용.

## 1. VectorStoreRetriever — 벡터 스토어 기반

벡터 스토어를 표준 Retriever 인터페이스로 변환하는 기본 검색기.

- `similarity`: 질문과 가까운 문서 우선
- `mmr`: 관련성과 결과 다양성의 균형
- `similarity_score_threshold`: 기준 점수 이상만 반환
- 빠른 기준선 구축과 RAG 파이프라인 연결에 적합

<details markdown="1">
<summary>예제 코드: MMR 검색기 생성과 호출</summary>

```python
retriever = vector_store.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 2, "fetch_k": 4, "lambda_mult": 0.7},
)

results = retriever.invoke("모터 이상 발생 시 점검 항목")
for document in results:
    print(document.metadata["document_id"], document.page_content)
```

메타데이터 필터 적용:

```python
filtered_retriever = vector_store.as_retriever(
    search_kwargs={"k": 2, "filter": {"equipment": "motor"}},
)
results = filtered_retriever.invoke("정비 주기와 점검 방법")
```

> 필터 문법은 벡터 스토어마다 차이. 사용 중인 저장소 문서 확인 필수.

</details>

## 2. ContextualCompressionRetriever — 문서 압축기

1차 검색 결과에서 질문과 관련된 부분만 추출하는 검색기.

- 기본 검색기와 문서 압축기의 조합
- 긴 문서의 불필요한 문맥 감소
- LLM 기반 추출 시 추가 호출 비용과 지연 발생
- 원문 보존이 필요한 업무의 출처 위치 별도 관리

<details markdown="1">
<summary>예제 코드: LLM 기반 관련 문장 추출</summary>

```python
from langchain_classic.retrievers import ContextualCompressionRetriever
from langchain_classic.retrievers.document_compressors import LLMChainExtractor

base_retriever = vector_store.as_retriever(search_kwargs={"k": 4})
compressor = LLMChainExtractor.from_llm(llm)
compression_retriever = ContextualCompressionRetriever(
    base_retriever=base_retriever,
    base_compressor=compressor,
)

results = compression_retriever.invoke("모터 진동 원인과 조치")
for document in results:
    print(document.page_content)
```

```text
질문 → 후보 문서 검색 → 관련 구간 추출 → 압축 Document 반환
```

</details>

## 3. EnsembleRetriever — 앙상블

서로 다른 검색 결과를 결합하는 하이브리드 검색기.

- BM25: 정확한 키워드·제품명·코드 검색에 강점
- Vector Search: 의미가 비슷한 표현 검색에 강점
- Weighted Reciprocal Rank Fusion 기반 순위 결합
- 가중치 합보다 검색 결과의 순위 활용

<details markdown="1">
<summary>예제 코드: BM25와 벡터 검색 결합</summary>

```python
from langchain_classic.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever

bm25_retriever = BM25Retriever.from_documents(documents)
bm25_retriever.k = 3
vector_retriever = vector_store.as_retriever(search_kwargs={"k": 3})

ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.4, 0.6],
)

results = ensemble_retriever.invoke("M-002 모터 축 정렬")
for document in results:
    print(document.metadata["document_id"], document.page_content)
```

> 고유 코드 중심 데이터는 BM25 가중치, 자연어 질문 중심 데이터는 벡터 검색 가중치 우선 검토.

</details>

## 4. LongContextReorder — 긴 문맥 재정렬

관련성이 높은 문서를 문맥의 앞과 뒤에 배치하는 문서 변환기.

- 긴 입력의 중간 정보 활용 저하 문제 완화
- 검색기가 아닌 Retriever 후처리용 Transformer
- 추가 모델 호출 없는 문서 순서 변경
- 문서 수가 많은 장문 프롬프트에 적합

<details markdown="1">
<summary>예제 코드: 검색 결과 재배치</summary>

```python
from langchain_community.document_transformers import LongContextReorder

retriever = vector_store.as_retriever(search_kwargs={"k": 4})
retrieved_documents = retriever.invoke("설비 점검과 안전 조치")

reordering = LongContextReorder()
reordered_documents = reordering.transform_documents(retrieved_documents)

for index, document in enumerate(reordered_documents, start=1):
    print(index, document.metadata["document_id"])

context = "\n\n".join(
    document.page_content for document in reordered_documents
)
```

</details>

## 5. ParentDocumentRetriever — 부모 문서 반환

작은 자식 청크로 검색하고 더 큰 부모 문서를 반환하는 계층형 검색기.

- 작은 청크의 정밀한 임베딩 검색
- 큰 청크의 충분한 답변 문맥
- 자식 청크는 VectorStore, 부모 문서는 DocStore에 저장
- 부모 문서 ID 연결의 일관성 필수

<details markdown="1">
<summary>예제 코드: 자식 청크 검색과 부모 문서 반환</summary>

```python
from langchain_chroma import Chroma
from langchain_classic.retrievers import ParentDocumentRetriever
from langchain_core.stores import InMemoryStore
from langchain_text_splitters import RecursiveCharacterTextSplitter

parent_splitter = RecursiveCharacterTextSplitter(chunk_size=500)
child_splitter = RecursiveCharacterTextSplitter(chunk_size=120)

parent_vector_store = Chroma(
    collection_name="parent_document_example",
    embedding_function=embeddings,
)
parent_store = InMemoryStore()

parent_retriever = ParentDocumentRetriever(
    vectorstore=parent_vector_store,
    docstore=parent_store,
    parent_splitter=parent_splitter,
    child_splitter=child_splitter,
)

parent_retriever.add_documents(documents)
results = parent_retriever.invoke("베어링 마모 점검")

for document in results:
    print(len(document.page_content), document.page_content)
```

> `InMemoryStore` 데이터는 프로세스 종료 시 소멸. 운영 환경은 영속 DocStore 적용.

</details>

## 6. MultiQueryRetriever — 다중 쿼리

하나의 질문을 여러 관점의 검색어로 바꿔 결과를 합치는 검색기.

- 표현 차이로 누락되는 관련 문서 보완
- 여러 검색 결과의 중복 제거
- 모호하거나 짧은 질문의 Recall 개선
- 쿼리 생성용 LLM 호출 비용과 지연 발생

<details markdown="1">
<summary>예제 코드: 질문 변형과 결과 통합</summary>

```python
from langchain_classic.retrievers.multi_query import MultiQueryRetriever

base_retriever = vector_store.as_retriever(search_kwargs={"k": 2})
multi_query_retriever = MultiQueryRetriever.from_llm(
    retriever=base_retriever,
    llm=llm,
    include_original=True,
)

results = multi_query_retriever.invoke("모터가 평소보다 흔들려요")
for document in results:
    print(document.metadata["document_id"], document.page_content)
```

생성 쿼리 확인용 로그:

## 7. MultiVectorRetriever — 다중 벡터 스토어

하나의 원문을 여러 자식 벡터로 검색하고 연결된 원문을 반환하는 검색기.

- 원문별 요약·질문·작은 청크 등 복수 벡터 표현
- 벡터 스토어에 자식 문서와 부모 ID 저장
- DocStore에 반환할 원문 저장
- 다양한 검색 관점과 원문 문맥의 동시 확보

<details markdown="1">
<summary>예제 코드: 요약 벡터 검색과 원문 반환</summary>

```python
from uuid import uuid4

from langchain_chroma import Chroma
from langchain_classic.retrievers.multi_vector import MultiVectorRetriever
from langchain_core.documents import Document
from langchain_core.stores import InMemoryByteStore

id_key = "doc_id"
doc_ids = [str(uuid4()) for _ in documents]
summary_texts = [
    "프레스 유압과 누유 일일 점검",
    "모터 진동, 베어링 마모, 축 정렬 점검",
    "컨베이어 비상 정지와 안전 조치",
    "모터 윤활유 정기 교체 주기",
]
summary_documents = [
    Document(page_content=summary, metadata={id_key: doc_ids[index]})
    for index, summary in enumerate(summary_texts)
]

multi_vector_store = Chroma(
    collection_name="multi_vector_example",
    embedding_function=embeddings,
)
byte_store = InMemoryByteStore()
multi_vector_retriever = MultiVectorRetriever(
    vectorstore=multi_vector_store,
    byte_store=byte_store,
    id_key=id_key,
)

multi_vector_retriever.vectorstore.add_documents(summary_documents)
multi_vector_retriever.docstore.mset(list(zip(doc_ids, documents)))

results = multi_vector_retriever.invoke("축 정렬 불량 징후")
for document in results:
    print(document.metadata["document_id"], document.page_content)
```

> 요약 자동 생성 시 별도 LLM 호출과 요약 품질 평가 필요.

</details>

## 8. SelfQueryRetriever — 셀프 쿼리

자연어 질문을 의미 검색어와 메타데이터 필터로 구조화하는 검색기.

- 질문 속 연도·범주·우선순위 조건 추출
- 벡터 검색과 구조화 필터의 동시 적용
- 정확한 필드 설명과 타입 정의 필수
- 사용자 권한 필터는 LLM 생성 결과와 별도로 강제 적용

<details markdown="1">
<summary>예제 코드: 자연어 조건을 메타데이터 필터로 변환</summary>

```python
from langchain_chroma import Chroma
from langchain_classic.chains.query_constructor.base import AttributeInfo
from langchain_classic.retrievers.self_query.base import SelfQueryRetriever

self_query_store = Chroma.from_documents(
    documents=documents,
    embedding=embeddings,
    collection_name="self_query_example",
)
metadata_field_info = [
    AttributeInfo(
        name="equipment",
        description="설비 종류: press, motor, conveyor",
        type="string",
    ),
    AttributeInfo(name="year", description="문서 작성 연도", type="integer"),
    AttributeInfo(
        name="priority",
        description="중요도: 1에서 3 사이의 정수",
        type="integer",
    ),
]

self_query_retriever = SelfQueryRetriever.from_llm(
    llm=llm,
    vectorstore=self_query_store,
    document_contents="설비 점검과 안전 조치 매뉴얼",
    metadata_field_info=metadata_field_info,
    enable_limit=True,
)

results = self_query_retriever.invoke(
    "2025년에 작성된 중요도 3의 설비 문서 2개"
)
for document in results:
    print(document.metadata, document.page_content)
```

> 벡터 스토어별 지원 비교 연산자와 필터 기능 확인 필수.

</details>

## 9. TimeWeightedVectorStoreRetriever — 시간 가중 벡터 스토어

의미 유사도와 최근 접근 시간을 함께 반영하는 검색기.

- 최근 문서에 높은 점수 부여
- 시간이 지날수록 점수 감쇠
- 검색된 문서의 최근 접근 시각 갱신
- 대화 기억, 뉴스, 최신 활동 기반 추천에 적합

<details markdown="1">
<summary>예제 코드: 유사도와 최신성 결합</summary>

```python
import faiss

from langchain_classic.retrievers import TimeWeightedVectorStoreRetriever
from langchain_community.docstore import InMemoryDocstore
from langchain_community.vectorstores import FAISS

embedding_size = len(embeddings.embed_query("벡터 차원 확인"))
index = faiss.IndexFlatL2(embedding_size)
time_vector_store = FAISS(
    embeddings,
    index,
    InMemoryDocstore({}),
    {},
)
time_retriever = TimeWeightedVectorStoreRetriever(
    vectorstore=time_vector_store,
    decay_rate=0.01,
    k=2,
)

time_retriever.add_documents(documents)
results = time_retriever.invoke("모터 유지보수")
for document in results:
    print(document.metadata["document_id"], document.page_content)
```

```text
낮은 decay_rate → 오래된 문서의 영향 장기 유지
높은 decay_rate → 최근 문서 중심의 빠른 감쇠
```

> 최신성과 정확성은 별개. 안전 규정·법령·승인 문서의 유효성 검증 별도 적용.

</details>

## Retriever 선택 가이드

| 요구 사항 | 권장 방식 |
| --- | --- |
| 기본 의미 검색 | VectorStoreRetriever |
| 긴 문서의 관련 부분만 사용 | ContextualCompressionRetriever |
| 키워드와 의미 검색 결합 | EnsembleRetriever |
| 긴 프롬프트의 문서 순서 개선 | LongContextReorder |
| 작은 청크로 찾고 큰 문맥 반환 | ParentDocumentRetriever |
| 질문 표현을 여러 방식으로 확장 | MultiQueryRetriever |
| 원문 하나에 여러 검색 표현 사용 | MultiVectorRetriever |
| 자연어 조건을 메타데이터 필터로 변환 | SelfQueryRetriever |
| 의미 유사도와 최신성 결합 | TimeWeightedVectorStoreRetriever |

## 운영 점검

- 실제 질문 세트 기반 Recall@k와 Precision@k 측정
- 검색 결과의 문서 ID·출처·버전 추적
- 문서 중복과 오래된 버전 제거 정책
- 사용자 권한 필터의 서버 측 강제 적용
- LLM 사용 검색기의 비용·지연·실패 처리
- 인메모리 저장소의 영속 저장소 전환
- 검색 결과가 없는 경우의 답변 정책
