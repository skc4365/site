## 검토 결과

기존 문서는 기본 VectorStoreRetriever만 포함합니다. 검색 품질을 개선하려면 키워드·벡터 결합, 다중 질의, 부모 문서, 메타데이터 필터, 압축 검색의 차이를 알아야 합니다.

## 1. 기본 벡터 리트리버

```python
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

documents = [
    Document(page_content="프레스 진동 점검 절차", metadata={"machine": "press"}),
    Document(page_content="용접기 냉각수 교체 절차", metadata={"machine": "welder"}),
]
store = InMemoryVectorStore.from_documents(
    documents,
    OpenAIEmbeddings(model="text-embedding-3-small"),
)
retriever = store.as_retriever(search_kwargs={"k": 2})
print(retriever.invoke("프레스가 흔들립니다"))
```

## 2. 하이브리드 검색 개념

```text
사용자 질문
  ├─ BM25·Kiwi: 모델명, 부품 번호, 정확한 용어 검색
  └─ Vector: 표현이 달라도 의미가 비슷한 문서 검색
           ↓
       순위 결합 → 상위 문서
```

제조 현장 데이터에는 부품 번호처럼 정확히 일치해야 하는 값이 많으므로 벡터 검색만 사용하지 말고 키워드 검색과 결합해 평가합니다.

## 3. 검색 평가

```python
test_cases = [
    {"query": "P-101 진동 경고", "expected_ids": {"manual-P101", "alarm-P101"}},
    {"query": "냉각수가 부족합니다", "expected_ids": {"coolant-guide"}},
]

for case in test_cases:
    found = {doc.metadata.get("id") for doc in retriever.invoke(case["query"])}
    hit = bool(found & case["expected_ids"])
    print(case["query"], "PASS" if hit else "FAIL", found)
```

## 선택 기준

- 정확한 용어와 식별자는 BM25·Kiwi를 사용합니다.
- 표현이 다양한 자연어 질문은 벡터 검색을 사용합니다.
- 짧은 청크의 문맥이 부족하면 ParentDocumentRetriever를 검토합니다.
- 질문 표현이 모호하면 MultiQueryRetriever를 검토합니다.
- 검색 문서가 길고 잡음이 많으면 ContextualCompression을 검토합니다.
- 방식 추가 전후를 동일한 평가 질문으로 비교합니다.
