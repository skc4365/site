# 다중 모델 챗봇 — 같은 인터페이스로 여러 공급자 모델을 선택하는 구조

## 개념

**다중 모델 챗봇**은 공통 Chat Model 인터페이스 뒤에 여러 공급자 모델을 연결하고, 설정이나 요청에 따라 하나를 선택합니다.

## 언제 사용하는가

- 품질·비용·속도에 따라 모델을 선택할 때
- 주 모델 장애 시 대체 모델을 사용할 때
- 동일 평가셋으로 여러 모델을 비교할 때

## 아키텍처

```text
사용자 요청 → Model Router
                ├─ OpenAI
                ├─ Anthropic
                └─ Local Model
                     ↓
              공통 AIMessage 응답
```

## 핵심 원리

| 전략 | 동작 |
|---|---|
| Selection | 사용자가 모델을 직접 선택 |
| Routing | 요청 특성에 맞는 모델을 선택 |
| Fallback | 주 모델 실패 시 대체 모델 사용 |

공통 `invoke()`를 사용해도 Context 한도, Tool Calling, 구조화 출력과 안전 정책은 다를 수 있습니다.

## 바로 실행하는 코드

```bash
pip install -U langchain-openai
```

`OPENAI_API_KEY` 환경 변수를 설정한 뒤 실행합니다. 두 모델 ID는 계정에서 사용할 수 있는 모델로 변경할 수 있습니다.

```python
from langchain_openai import ChatOpenAI

models = {
    "fast": ChatOpenAI(model="gpt-4.1-mini", temperature=0),
    "quality": ChatOpenAI(model="gpt-4.1", temperature=0),
}


def ask(question: str, selected: str = "fast") -> str:
    if selected not in models:
        raise ValueError(f"지원하지 않는 모델: {selected}")
    response = models[selected].invoke(question)
    return response.content


print(ask("RAG를 한 문장으로 설명해줘.", selected="fast"))
```

## 요점 정리

1. 모델 추상화는 호출 방식을 통일합니다.
2. 공급자별 기능 차이까지 없애 주는 것은 아닙니다.
3. Routing은 요청 전에 선택하고 Fallback은 실패 후 전환합니다.
4. 모델별 품질·지연·비용·스키마 통과율을 비교합니다.
5. 모델 교체 후 같은 평가셋으로 회귀 테스트합니다.
