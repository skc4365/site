# AI 에이전트 최적화 2

**최적화 범위:** 추론 효율 · 도구 호출 정확도 · 메모리 관리 · 비용 제어 · 안전성

```text
요청 분류 → 실행 경로 선택 → 도구 호출 → 상태 갱신 → 결과 검증 → 평가
```

## 1. 시스템 구조 최적화

### 단일·멀티 에이전트 선택

| 구조 | 적합한 상황 | 주의점 |
|---|---|---|
| 단일 에이전트 | 짧고 단순한 과업, 적은 도구 | 복합 역할 증가 시 프롬프트 복잡도 상승 |
| 멀티 에이전트 | 역할·권한·평가 기준의 명확한 분리 | 호출량·지연시간·상태 동기화 비용 증가 |
| 결정적 Workflow | 순서와 규칙이 고정된 업무 | 예외 경로의 명시적 설계 필요 |

**역할 분리 예시:** 기획 · 검색 · 실행 · 검수

**선택 기준:** 역할별 독립성 · 도구 권한 · 병렬성 · 실패 격리 · 추가 비용

### 라우팅

- 고정 안내: 규칙·템플릿
- 단일 데이터 조회: 직접 Tool Call
- 문서 근거 기반 질문: RAG
- 복합 계획과 도구 조합: Agent
- 쓰기·삭제·외부 전송: 승인 포함 Workflow

**효과:** 불필요한 모델 호출 감소 · 예측 가능한 실행 · 비용·지연시간 절감

### 결정적 제어

- 최대 실행 단계
- 전체 timeout
- 도구별 재시도 횟수
- 동일 도구·인자 반복 차단
- 허용 도구 목록
- 완료·중단 조건
- 쓰기 작업 승인 게이트

## 2. 지연시간과 비용 최적화

### 실행 계층

- 독립적인 읽기 도구의 비동기·병렬 호출
- 의존 관계가 있는 작업의 순차 실행
- 동일 조회 결과 캐시
- Tool 응답의 필요 필드만 Context에 포함
- 단순 작업용 경량 모델 라우팅
- 복합 판단 단계의 고성능 모델 제한 사용

### 병렬 실행 기준

| 작업 | 처리 방식 |
|---|---|
| 생산량 조회 + 불량률 조회 | 병렬 가능 |
| 문서 검색 + 설비 상태 조회 | 병렬 가능 |
| 정비 요청 생성 → 승인 | 순차 실행 |
| 주문 생성 → 결제 | 순차 실행 |
| 동일 데이터 수정 | 충돌 제어 후 순차 실행 |

### 캐시 기준

**적용 후보:** 반복 질문 · 정적 문서 검색 · 변화 없는 기준 정보 · 동일 Tool 입력

**적용 주의:** 실시간 센서 · 사용자별 권한 결과 · 쓰기 작업 · 민감 정보 · 짧은 유효기간 데이터

### 모델 서빙 계층

**추측성 디코딩:** 작은 초안 모델의 후보 토큰 생성 + 큰 모델의 병렬 검증

**적용 위치:** 자체 모델 추론 서버 또는 기능 지원 API

**구분:** Agent Workflow 최적화가 아닌 모델 추론 인프라 최적화

## 3. 도구 최적화

### Tool Schema

- 하나의 도구, 하나의 책임
- 명확한 동사형 이름
- 입력 타입·형식·단위·범위
- 필수값과 선택값 구분
- 정상·오류 반환 구조
- 읽기·쓰기 도구 분리
- 유사 도구 간 선택 기준

### 반환값 표준

| 필드 | 내용 |
|---|---|
| `status` | `success`, `partial`, `error` |
| `data` | 구조화된 실행 결과 |
| `error_code` | 기계 판독용 오류 코드 |
| `message` | 사용자 안내 메시지 |
| `source` | 데이터 출처 |
| `data_timestamp` | 데이터 기준 시각 |

### 실패 처리

| 오류 | 정책 |
|---|---|
| 일시적 네트워크 오류 | 제한된 지수 백오프 재시도 |
| 입력 검증 오류 | 오류 내용을 반영한 1회 수정 |
| 권한 부족 | 즉시 중단·권한 안내 |
| 데이터 없음 | 조건 확인 또는 근거 부족 응답 |
| 안전 정책 위반 | 재시도 없이 차단 |

## 4. 메모리와 Context 최적화

### 메모리 분리

| 유형 | 내용 | 관리 기준 |
|---|---|---|
| 작업 메모리 | 현재 과업의 단계·도구 결과 | 요청 종료 후 제거 |
| 세션 메모리 | 현재 대화의 결정·선호 | 세션 범위 유지 |
| 장기 메모리 | 반복 활용 정보 | 동의·출처·만료 시점 관리 |
| 지식 저장소 | 규정·매뉴얼·업무 문서 | 버전·권한·폐기 정책 |

### Context 우선순위

1. 시스템 정책과 안전 규칙
2. 현재 요청과 제약조건
3. 승인 상태와 사용자 권한
4. 최신 Tool 결과
5. 관련 문서 근거
6. 압축된 대화 요약
7. 장기 메모리

### 압축 대상

- 오래된 대화의 요약
- 중복 Tool 결과 제거
- 전체 API 응답 대신 필요 필드 선택
- 해결된 오류와 이전 계획 제거
- RAG 문서의 중복 구간 제거

### 저장 제외

- 비밀번호·API Key
- 불필요한 개인정보
- 검증되지 않은 추론
- 일시적 오류 메시지
- 출처와 갱신 시점이 없는 정보

## 5. 관측성과 평가

### Trace 항목

- 요청·세션·사용자 범위 식별자
- 입력 분류와 선택 경로
- 모델·프롬프트·Tool 버전
- Tool 이름·입력·결과 상태
- 단계별 시작·종료 시각
- 토큰·지연시간·비용
- 재시도·중단·오류 이유
- 승인 요청과 결과
- 최종 응답과 근거

### 평가 지표

| 평가 축 | 지표 |
|---|---|
| 목표 달성 | Task Success Rate |
| 경로 선택 | Route Accuracy |
| 도구 선택 | Tool Selection Accuracy |
| 인자 생성 | Argument Validity Rate |
| 실행 효율 | 평균 Step·Tool Call 수 |
| 성능 | P50·P95 지연시간 |
| 비용 | 요청당 토큰·도구 비용 |
| 안정성 | 오류·재시도·timeout 비율 |
| 안전성 | 승인 우회·금지 행동 실행률 |

### 평가 방식

- 규칙 평가: 형식·단계·도구·인자·금지 행동
- 코드 평가: 계산값·상태 변경·API 결과
- 전문가 평가: 업무 적합성·안전성·예외 판단
- LLM 평가: 관련성·완결성·표현 품질의 보조 판정

**LLM Judge 주의점:** 기준 답안·평가 기준표 · 다중 평가 · 사람 검토와 함께 사용
