# LLM 모델 이름 읽는 법과 대표 모델

처음 LLM을 접하면 `GPT`, `Claude`, `Gemini`, `Llama`, `Qwen`처럼 이름이 너무 많아 당황하기 쉽습니다. 하지만 대부분의 모델 이름은 다음 정보를 조합해 만듭니다.

```text
제공사/제품군 + 세대 + 성능 등급 + 전문 기능 + 크기 + 학습 방식 + 배포 버전
```

예를 들어 `Qwen3-Coder-30B-A3B-Instruct`는 다음처럼 읽습니다.

- `Qwen3`: Qwen 제품군의 3세대
- `Coder`: 코딩 특화
- `30B`: 전체 파라미터가 약 300억 개
- `A3B`: MoE 구조에서 한 번의 추론에 약 30억 개가 활성화됨
- `Instruct`: 사람의 명령을 따르도록 추가 학습된 대화용 모델

> 모델 이름은 제품의 방향을 알려 주지만 성능 전체를 보장하지는 않습니다. 실제 선택에서는 품질, 속도, 비용, 입력 형식, 컨텍스트 길이, 보안, 배포 위치를 함께 확인해야 합니다.

## 1. 이름에 자주 등장하는 단어

| 이름 조각 | 일반적인 뜻 | 선택할 때의 해석 |
|---|---|---|
| `Pro`, `Opus`, `Large` | 해당 제품군의 고성능 등급 | 복잡한 분석·코딩·에이전트에 적합하지만 대체로 느리고 비쌈 |
| `Sonnet`, `Medium` | 품질·속도·비용의 균형형 | 특별한 이유가 없다면 업무용 기본 모델로 시작하기 좋음 |
| `Mini`, `Nano`, `Haiku`, `Flash`, `Lite`, `Small` | 작고 빠르며 저렴한 등급 | 분류·추출·요약·대량 처리·실시간 응답에 적합 |
| `Reasoning`, `Thinking`, `o-series`, `R` | 답하기 전에 더 많은 추론 계산 사용 | 수학·논리·설계·복잡한 문제 해결에 유리하며 지연과 비용이 늘 수 있음 |
| `Chat`, `Instruct`, `IT` | 지시 수행과 대화에 맞게 후처리된 모델 | 챗봇과 일반 애플리케이션에서는 보통 이 변형을 선택 |
| `Base`, `PT` | 사전 학습만 된 기반 모델 | 연구·파인튜닝용이며 일반 대화에 바로 쓰기에는 부적합할 수 있음 |
| `Coder`, `Code`, `Codex`, `Devstral` | 코드 생성·수정·도구 사용에 특화 | 개발 보조, 코드 리뷰, 저장소 단위 작업에 적합 |
| `Vision`, `VL`, `Multimodal`, `Omni` | 이미지·음성 등 텍스트 외 입력 지원 | 이미지 설명, 문서 화면 분석, 음성 대화 등에 사용 |
| `Embedding` | 텍스트·이미지를 숫자 벡터로 변환 | RAG 검색·유사도·군집화용이며 채팅 답변 생성 모델은 아님 |
| `Rerank` | 검색된 문서의 순서를 다시 평가 | RAG 검색 정확도를 높이는 보조 모델 |
| `Realtime`, `Live` | 낮은 지연의 스트리밍 상호작용 | 실시간 음성 대화와 인터랙티브 서비스에 적합 |
| `Audio`, `TTS`, `Transcribe`, `Voxtral` | 음성 생성 또는 음성 인식 | TTS는 글→음성, Transcribe는 음성→글 |
| `OCR` | 문서 이미지에서 문자·표·구조 추출 | 스캔 PDF와 영수증·계약서 처리에 적합 |
| `7B`, `32B`, `70B`, `120B` | 대략적인 전체 파라미터 수 | 대체로 클수록 높은 자원과 메모리가 필요하지만 항상 더 우수한 것은 아님 |
| `A3B`, `A22B`, `MoE` | 전체 중 일부 전문가 파라미터만 활성화 | 큰 총용량을 유지하면서 추론 계산량을 줄이는 구조 |
| `Q4`, `Q5`, `Q8`, `FP16`, `BF16` | 가중치 정밀도 또는 양자화 수준 | 숫자가 낮을수록 메모리는 절약되지만 품질이 일부 낮아질 수 있음 |
| `Preview`, `Experimental` | 정식 안정판 이전 버전 | 기능 검증용이며 API·동작·지원 기간이 바뀔 수 있음 |
| `Latest` | 제공사가 최신 스냅샷으로 이동시키는 별칭 | 편리하지만 재현성이 중요하면 고정된 모델 ID를 사용 |
| 날짜·버전 (`20251001`, `4.6`, `2507`) | 특정 릴리스나 스냅샷 | 운영 환경에서는 버전을 고정해야 결과 변화를 줄일 수 있음 |

## 2. API로 많이 접하는 대표 모델 계열

아래의 모델명은 이름 구조를 이해하기 위한 대표 계열입니다. 제공사가 모델을 자주 추가·교체하므로 실제 API에서 사용할 정확한 ID는 각 제공사의 모델 목록을 다시 확인합니다.

| 제공사 | 대표 모델명·계열 | 이름이 뜻하는 것 | 강점과 대표 용도 | 처음 선택한다면 |
|---|---|---|---|---|
| OpenAI | `GPT-5`, `GPT-5 mini`, `GPT-5 nano`, `GPT-5 pro` | 숫자는 세대, `mini/nano`는 속도·비용 최적화, `pro`는 더 많은 계산을 쓰는 고성능형 | 범용 질의, 코딩, 도구 호출, 구조화 출력, 에이전트 | 일반 업무는 기본/mini, 복잡한 분석은 기본/pro, 대량 단순 처리는 nano |
| OpenAI | `GPT-… Codex` | GPT 계열 중 에이전트형 코딩 작업에 최적화 | 코드 작성·수정, 테스트, 저장소 단위 작업 | 소프트웨어 개발 자동화가 주목적일 때 |
| OpenAI | `o…`, `…reasoning` | 추론 계산을 강화한 계열 | 수학, 논리, 계획, 난도가 높은 문제 해결 | 빠른 대화보다 정답률과 사고가 중요할 때 |
| OpenAI | `…realtime`, `…audio`, `…transcribe`, `…tts` | 실시간·음성 입출력·음성 인식·음성 합성 전용 | 음성 비서, 콜봇, 회의 기록 | 입력과 출력 형식에 맞는 전용 모델 선택 |
| Anthropic | `Claude Opus` | 가장 높은 성능 등급 | 복잡한 추론, 긴 작업, 에이전트형 코딩 | 품질이 비용·속도보다 중요할 때 |
| Anthropic | `Claude Sonnet` | 성능과 속도의 균형 등급 | 코딩, 문서 분석, 일반적인 운영 워크로드 | Claude를 처음 적용할 때의 기본 선택 |
| Anthropic | `Claude Haiku` | 가장 빠르고 경제적인 등급 | 분류, 추출, 간단한 질의, 대량 처리 | 낮은 지연과 처리량이 중요할 때 |
| Google | `Gemini Pro` | 복잡한 작업을 위한 고성능 등급 | 추론, 코딩, 긴 문서와 멀티모달 분석 | 높은 품질이 필요한 복합 작업 |
| Google | `Gemini Flash` | 속도·가격·품질 균형형 | 대화, 요약, 추출, 에이전트, 멀티모달 처리 | Gemini의 일반적인 기본 선택 |
| Google | `Gemini Flash-Lite` | Flash보다 비용과 지연을 더 낮춘 경량형 | 대량 분류·추출·간단한 자동화 | 단순 요청을 매우 많이 처리할 때 |
| DeepSeek | `DeepSeek-V…-Pro` | 세대 표시 `V`와 고성능 등급 `Pro` | 복잡한 코딩·추론·에이전트 작업 | DeepSeek에서 품질 우선 모델이 필요할 때 |
| DeepSeek | `DeepSeek-V…-Flash` | 빠르고 경제적인 범용형이며 thinking/non-thinking 모드를 제공할 수 있음 | 채팅, 코딩, 비용 효율적인 추론 | 범용 기본 모델과 대량 처리 |
| Mistral AI | `Mistral Medium`, `Mistral Small` | 회사명/제품군과 성능 등급 | 범용 대화, 코딩, 에이전트, 멀티모달 | Medium은 품질 균형, Small은 비용·속도 우선 |
| Mistral AI | `Devstral`, `Codestral` | 개발·코드 작업에 특화된 모델명 | 코드베이스 탐색, 코드 생성·수정 | 프로그래밍이 주목적일 때 |
| Mistral AI | `Voxtral`, `OCR` | 음성 또는 문서 인식 전용 계열 | 음성 전사, 실시간 음성, 문서 구조 추출 | 생성형 채팅이 아니라 해당 입력 처리용 |

## 3. 로컬 실행에서 자주 보는 오픈 웨이트 모델

| 대표 모델명 | 이름 해독 | 특징과 용도 | 주의할 점 |
|---|---|---|---|
| `gpt-oss-20b` | OpenAI 오픈 웨이트, 약 200억 파라미터 | 비교적 낮은 지연의 로컬·특화 작업, 추론과 도구 사용 | 하드웨어에 맞는 양자화와 공식 대화 형식 확인 |
| `gpt-oss-120b` | OpenAI 오픈 웨이트, 약 1,200억 파라미터 | 더 복잡한 범용 추론과 에이전트 작업 | 큰 GPU 메모리와 서빙 환경 필요 |
| `Llama-…-8B-Instruct` | Meta Llama 계열, 약 80억 파라미터, 지시 학습형 | 로컬 챗봇, 파인튜닝, 비교적 가벼운 실험 | `Base`보다 `Instruct`가 대화에 적합 |
| `Llama-…-70B-Instruct` | Llama 대형 지시 학습형 | 더 높은 품질의 생성·추론 | 단일 소비자 GPU에서 실행하기 어려울 수 있음 |
| `Qwen3-32B` | Qwen 3세대, 320억 dense 모델 | 다국어, 추론, 코딩, 도구 사용 | thinking 모드와 실행 프레임워크 설정 확인 |
| `Qwen3-30B-A3B` | 전체 300억, 추론 시 약 30억 활성화하는 MoE | 계산 효율과 모델 용량의 균형 | 전체 모델 저장 메모리와 활성 파라미터는 다른 개념 |
| `Qwen3-Coder-…-Instruct` | Qwen 3세대 코딩 특화 지시 모델 | 에이전트형 코딩, 저장소 작업, 도구 호출 | 모델 크기와 컨텍스트 설정에 따라 요구 자원이 큼 |
| `Gemma-…-4B-IT` | Google Gemma 계열, 40억, instruction-tuned | 노트북·데스크톱에서 가벼운 대화와 이미지 이해 | `IT`와 사전 학습형 `PT`를 구분 |
| `Gemma-…-27B-IT` | Gemma 대형 지시 학습형 | 더 높은 품질의 질의응답·요약·추론 | 4B보다 훨씬 많은 메모리 필요 |
| `Mistral-Small-…-Instruct` | Mistral 경량 범용 지시 모델 | 로컬·서버의 범용 대화와 코딩 | 이름 끝 날짜는 릴리스 스냅샷인 경우가 많음 |

### 파라미터 크기와 내 PC의 관계

| 표시 | 대략적인 의미 | 로컬 실행 감각 |
|---|---|---|
| `1B~4B` | 10억~40억 파라미터 | 노트북·일부 모바일에서도 양자화 모델 실행 가능, 빠르지만 복잡한 작업은 제한적 |
| `7B~14B` | 70억~140억 파라미터 | 개인 PC에서 가장 많이 실험하는 구간, 메모리와 품질의 균형 |
| `20B~32B` | 200억~320억 파라미터 | 넉넉한 GPU 메모리나 CPU 오프로딩 필요, 품질 향상을 기대할 수 있음 |
| `70B 이상` | 700억 이상 파라미터 | 고사양 멀티 GPU나 서버·클라우드가 현실적 |

> `B`만 보고 필요한 VRAM을 정확히 계산할 수는 없습니다. 정밀도, 양자화, 컨텍스트 길이, KV 캐시, 동시 사용자 수가 메모리 사용량을 크게 바꿉니다.

## 4. 목적별 빠른 선택표

| 내가 하려는 일 | 먼저 살펴볼 모델 유형 | 이유 |
|---|---|---|
| 처음 API 챗봇 만들기 | 균형형: `Sonnet`, `Flash`, 기본 GPT 또는 `mini` | 품질·속도·비용의 균형이 좋고 예제가 많음 |
| 문서 분류·정보 추출을 대량 처리 | `Mini`, `Nano`, `Haiku`, `Flash-Lite`, `Small` | 단순하고 반복적인 요청의 비용과 지연 절감 |
| 어려운 수학·논리·계획 | `Pro`, `Opus`, reasoning/thinking 모델 | 더 많은 추론 계산을 사용하도록 설계 |
| 코드 작성과 저장소 수정 | `Codex`, `Coder`, `Codestral`, `Devstral` 또는 강한 Sonnet 계열 | 코드와 도구 사용에 특화 |
| RAG 문서 검색 | 생성 모델 + `Embedding` + 필요 시 `Rerank` | 답변 생성과 검색은 서로 다른 역할이기 때문 |
| 이미지·PDF 화면 이해 | `Vision`, `VL`, `Multimodal`, `Omni` | 텍스트 외 입력을 받을 수 있음 |
| 음성 비서·콜봇 | `Realtime/Live` + `Transcribe` + `TTS/Audio` | 낮은 지연의 음성 입출력에 특화 |
| 사내망·개인 PC에서 실행 | `Instruct/IT` 오픈 웨이트 모델 + 적절한 `Q4/Q5/Q8` | 데이터 통제와 오프라인 실행 가능 |
| 모델 파인튜닝 연구 | `Base/PT` 또는 파인튜닝 허용 오픈 웨이트 | 대화 후처리 이전의 기반 가중치 활용 가능 |

## 5. 초보자가 기억할 핵심

1. **제품군보다 용도를 먼저 정합니다.** 채팅, 코딩, 검색, 음성, 이미지 중 무엇이 필요한지 결정합니다.
2. **처음에는 균형형 모델로 시작합니다.** 품질이 부족하면 상위 등급, 비용이 크면 경량 등급으로 이동합니다.
3. **RAG에는 모델이 최소 두 종류 필요합니다.** 답변용 생성 모델과 검색용 임베딩 모델의 역할이 다릅니다.
4. **로컬 모델은 `Instruct/IT`를 우선 봅니다.** `Base/PT`는 주로 연구와 추가 학습용입니다.
5. **API에서는 모델 ID를 고정합니다.** `latest` 별칭은 편하지만 모델 변경으로 결과가 달라질 수 있습니다.
6. **모델 이름만으로 결론 내리지 않습니다.** 작은 최신 모델이 큰 구형 모델보다 특정 작업에서 더 나을 수 있으므로 실제 데이터로 평가합니다.
