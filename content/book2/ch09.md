# Agentic RAG — 에이전트가 검색 여부와 도구를 선택하는 RAG 구조

## 개념

**Agentic RAG**는 매 질문마다 고정적으로 검색하지 않고, Agent가 현재 상황을 판단해 검색 도구의 사용 여부와 순서를 결정하는 방식입니다.

```text
2-step RAG: 질문 → 항상 검색 → 답변
Agentic RAG: 질문 → Agent 판단 → 필요할 때 검색 → 답변
```

## 언제 사용하는가

- 문서 검색, 웹 검색, 표 분석 등 여러 정보원이 있을 때
- 검색 결과가 부족하면 질문을 바꾸어 다시 검색해야 할 때
- 단순 대화와 지식 검색 요청이 한 서비스에 섞여 있을 때

항상 한 번만 검색하면 되는 문서 Q&A에는 2-step RAG가 더 단순하고 빠릅니다.

## 아키텍처

```text
사용자 질문 → Agent
                ├─ 바로 답변
                └─ 검색 Tool 호출
                       ↓
                  관련 문서 관찰
                       ├─ 충분함 → 근거 답변
                       └─ 부족함 → 질의 수정·다른 Tool
```

## 핵심 원리

검색기를 Agent가 호출할 수 있는 Tool로 감쌉니다.

```text
Retriever: query → Document 목록
Search Tool: query → 모델이 읽을 검색 결과
Agent: Search Tool을 언제 호출할지 결정
```

유연성은 높지만 모델 호출과 검색 횟수가 달라져 지연 시간과 비용을 예측하기 어려워집니다.

## 바로 실행하는 코드

```bash
pip install -U langchain langchain-openai
```

`OPENAI_API_KEY` 환경 변수를 설정한 뒤 실행합니다.

```python
from langchain.agents import create_agent
from langchain.tools import tool


DOCUMENTS = {
    "휴가": "연차 휴가는 그룹웨어에서 신청하고 팀장 승인을 받습니다.",
    "비밀번호": "비밀번호는 보안 포털의 계정 관리 메뉴에서 변경합니다.",
}


@tool
def search_company_guide(query: str) -> str:
    """회사 업무 지침에서 질문과 관련된 내용을 검색합니다."""
    found = [text for key, text in DOCUMENTS.items() if key in query]
    return "\n".join(found) if found else "관련 문서를 찾지 못했습니다."


agent = create_agent(
    model="openai:gpt-4.1-mini",
    tools=[search_company_guide],
    system_prompt=(
        "회사 규정 질문은 search_company_guide로 검색하세요. "
        "검색 결과에 없는 내용은 추측하지 마세요."
    ),
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "연차 휴가는 어떻게 신청해?"}]}
)
print(result["messages"][-1].content)
```

## 코드에서 볼 부분

```python
tools=[search_company_guide]
```

Agent는 검색 함수의 내부 구현을 알 필요가 없습니다. 도구 이름, 설명, 입력 스키마를 보고 필요할 때 호출합니다.

## 안전 경계

| 위험 | 대응 |
|---|---|
| 잘못된 검색 도구 선택 | 도구 설명과 평가셋 개선 |
| 검색 무한 반복 | 최대 실행 횟수·시간 제한 |
| 파일·코드 도구 오용 | 허용 경로·명령·권한 제한 |
| 근거 없는 답변 | 근거 부족 시 중단하는 규칙 |

## 요점 정리

1. Agentic RAG는 Agent가 검색 시점과 정보원을 선택합니다.
2. Retriever를 Tool로 감싸 Agent의 실행 루프에 연결합니다.
3. 유연성은 높지만 비용·지연 시간·실패 경로도 증가합니다.
4. 단순 문서 Q&A에는 2-step RAG가 더 적합할 수 있습니다.
5. 검색 횟수, 도구 권한, 근거 부족 시 종료 정책이 필요합니다.
