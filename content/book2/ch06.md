# LangSmith 평가 — 실행 기록을 데이터셋과 비교해 AI 품질을 관리하는 방법

## 개념

**LangSmith**는 LLM 애플리케이션의 실행 과정을 Trace로 기록하고, 평가 데이터셋으로 여러 버전의 품질을 비교하는 플랫폼입니다.

```text
Observability: 실제 실행을 기록하고 원인을 찾는다.
Evaluation:    같은 문제로 버전별 품질을 비교한다.
```

## 언제 사용하는가

- Prompt나 Model 변경 전후의 품질을 비교할 때
- Chain·Retriever·Tool 중 어느 단계에서 실패했는지 찾을 때
- 배포 전 회귀 테스트와 배포 후 품질 모니터링을 연결할 때

## 아키텍처

```text
[관찰]
사용자 요청 → Trace → 여러 Run(모델·검색·도구) → 지연·토큰·오류

[평가]
Dataset의 Example → Target 실행 → Evaluator 채점 → Experiment 비교
```

## 핵심 용어

| 용어 | 의미 |
|---|---|
| Trace | 사용자 요청 한 건의 전체 실행 기록 |
| Run | Trace 안의 개별 모델·검색·도구 실행 |
| Dataset | 반복 평가에 사용할 Example 모음 |
| Example | 입력과 선택적 기준 출력 한 쌍 |
| Evaluator | 실제 출력에 점수·판정을 부여하는 함수 |
| Experiment | 특정 버전을 Dataset 전체에 실행한 결과 |

```text
Experiment = Target(Dataset) + Evaluators + 실행 설정
```

## 바로 실행하는 추적 코드

```bash
pip install -U langsmith
```

`LANGSMITH_API_KEY`, `LANGSMITH_TRACING=true`, `LANGSMITH_PROJECT=book2-ch06`을 환경 변수로 설정합니다.

```python
from langsmith import traceable


@traceable(name="answer-uppercase")
def answer(question: str) -> str:
    # 실제 프로젝트에서는 이 안에서 RAG Chain이나 Agent를 호출합니다.
    return question.upper()


result = answer("langsmith는 무엇을 기록하나요?")
print(result)
```

실행 후 LangSmith 프로젝트에서 입력, 출력, 실행 시간과 오류 여부를 확인할 수 있습니다.

## 평가 코드의 핵심 형태

```python
from langsmith import evaluate

results = evaluate(
    target,                       # 평가할 Chain·함수
    data="rag-evaluation-set",    # 입력·기준 답변 Dataset
    evaluators=[correctness],     # 채점 함수
    experiment_prefix="prompt-v2",
)
```

같은 Dataset으로 `prompt-v1`과 `prompt-v2` Experiment를 만들면 품질, 지연 시간, 토큰 비용을 나란히 비교할 수 있습니다.

## 오프라인과 온라인 평가

| 구분 | 오프라인 평가 | 온라인 평가 |
|---|---|---|
| 시점 | 배포 전 | 배포 후 |
| 대상 | 고정 Dataset | 실제 Run·Thread |
| 목적 | 비교·회귀 테스트 | 이상 탐지·품질 모니터링 |
| 기준 답변 | 사용할 수 있음 | 없는 경우가 많음 |

## 요점 정리

1. Trace는 요청 한 건, Run은 그 안의 개별 실행 단계입니다.
2. Dataset은 문제 모음이고 Experiment는 특정 버전의 평가 결과입니다.
3. 오프라인 평가는 배포 전 비교, 온라인 평가는 실제 서비스 모니터링에 사용합니다.
4. 정확도뿐 아니라 지연 시간, 토큰, 오류도 함께 비교합니다.
5. 실패한 운영 Trace는 평가 Dataset에 추가해 재발을 막습니다.
