기존 문서는 LLM-as-a-Judge 한 종류만 포함합니다. 교육상 데이터셋 생성, 결정적 코드 평가, 버전 비교, pairwise 평가, 온라인 평가의 차이가 필요합니다.

| 원본 범주 | 필요성 |
| --- | --- |
| LangSmith Dataset | 필수 |

| Online Evaluation | 필수 운영 개념 |

## 데이터셋과 코드 평가자

```python
from langsmith import Client

client = Client()
dataset_name = "manufacturing-rag-eval"

if not client.has_dataset(dataset_name=dataset_name):
    dataset = client.create_dataset(dataset_name=dataset_name)
    client.create_examples(
        dataset_id=dataset.id,
        examples=[
            {
                "inputs": {"question": "비상 정지 후 첫 조치는?"},
                "outputs": {"required_keyword": "전원 차단"},
            }
        ],
    )


def contains_required_keyword(inputs: dict, outputs: dict, reference_outputs: dict) -> bool:
    return reference_outputs["required_keyword"] in outputs["answer"]
```

## 실험 실행

```python
def target(inputs: dict) -> dict:
    return {"answer": rag_chain.invoke(inputs["question"])}


results = client.evaluate(
    target,
    data=dataset_name,
    evaluators=[contains_required_keyword],
    experiment_prefix="rag-baseline",
)
```

## 평가 선택 기준

- 형식, 금칙어, 필수 키워드는 코드 평가자를 사용합니다.
- 의미적 정확성·친절성은 LLM-as-a-Judge를 사용하되 기준표를 명확히 작성합니다.
- 두 버전 중 어느 것이 나은지 판단할 때 pairwise 평가를 사용합니다.
- 배포 전에는 오프라인 평가, 배포 후에는 샘플링된 온라인 평가를 사용합니다.
- 실패한 운영 trace는 검수 후 회귀 테스트 데이터셋으로 편입합니다.
