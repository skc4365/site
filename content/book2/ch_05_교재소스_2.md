## 검토 결과

기존 문서는 준비된 데이터셋을 평가하는 과정만 포함합니다. 평가를 재현하려면 테스트 질문 생성, 데이터 스키마 검증, 검색과 답변의 분리 평가가 함께 필요합니다.

## 필요한 평가 데이터

| 필드 | 의미 |
| --- | --- |
| `user_input` | 사용자 질문 |
| `response` | RAG가 생성한 답변 |
| `retrieved_contexts` | 검색된 근거 청크 목록 |
| `reference` | 검수된 기준 답변 |

```python
evaluation_rows = [
    {
        "user_input": "모터 진동이 증가하면 무엇을 확인하나요?",
        "response": "베어링과 체결 상태를 점검합니다.",
        "retrieved_contexts": ["진동 증가 시 베어링 마모와 볼트 풀림을 확인한다."],
        "reference": "베어링 마모와 체결 볼트 풀림을 확인합니다.",
    }
]
```

## 평가 흐름

```text
대표 문서 선정
 → 질문·기준 답변 생성
 → 사람이 질문 가능성과 근거를 검수
 → 동일 데이터로 RAG 버전별 실행
 → 검색 품질과 답변 품질을 분리 평가
 → 낮은 점수 사례를 원인별로 분류
```

## 필수 평가 관점

- 검색 적합성: 검색 문서가 질문 해결에 필요한가?
- 근거 충실성: 답변이 검색 문서에 근거하는가?
- 답변 정확성: 기준 답변의 핵심 내용을 포함하는가?
- 답변 관련성: 질문과 무관한 설명이 섞이지 않았는가?

## 운영 원칙

- 합성 질문만 사용하지 말고 실제 사용자 질문을 함께 포함합니다.
- 모델이 만든 기준 답변은 반드시 사람이 검수합니다.
- 데이터셋과 평가 모델·프롬프트 버전을 기록합니다.
- 평균 점수뿐 아니라 최저 점수 사례와 실패 유형을 확인합니다.
- 라이브러리 버전에 따라 metric 이름과 입력 스키마가 달라질 수 있으므로 설치 버전의 공식 문서를 확인합니다.
