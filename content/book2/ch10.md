# Streamlit 배포 — Python AI 기능을 대화형 웹 화면으로 제공하는 방법

## 개념

**Streamlit**은 Python 스크립트를 입력 위젯과 출력 화면이 있는 웹 애플리케이션으로 실행하는 프레임워크입니다.

```text
Python 함수 + Streamlit UI → 브라우저에서 사용하는 웹 앱
```

## 언제 사용하는가

- RAG·Agent 기능을 빠르게 시연할 때
- 내부 사용자용 챗봇이나 데이터 앱을 만들 때
- 프론트엔드 프로젝트 없이 Python 중심으로 화면을 구성할 때

## 아키텍처

```text
브라우저 입력 → Streamlit Server → Python 스크립트 재실행
                     │
                     ├─ session_state: 사용자 상태
                     └─ cache_resource: 공유 가능한 무거운 객체
```

버튼이나 입력이 바뀌면 스크립트가 위에서 아래로 다시 실행됩니다. 따라서 일반 지역 변수만으로는 대화 기록을 유지할 수 없습니다.

## 핵심 원리

| 기능 | 수명과 용도 |
|---|---|
| 일반 변수 | 한 번의 실행 동안 사용 |
| `st.session_state` | 사용자 세션의 재실행 사이에 유지 |
| `st.cache_data` | 데이터 처리 결과를 캐시 |
| `st.cache_resource` | 모델·DB 연결 같은 리소스를 캐시 |

## 바로 실행하는 코드

```bash
pip install -U streamlit
```

다음 코드를 `app.py`로 저장합니다.

```python
import streamlit as st


@st.cache_resource
def load_service():
    # 실제 프로젝트에서는 RAG Chain이나 Agent를 생성합니다.
    return lambda question: f"처리된 질문: {question}"


st.title("간단한 AI 서비스")

if "messages" not in st.session_state:
    st.session_state.messages = []

for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.write(message["content"])

if question := st.chat_input("질문을 입력하세요"):
    st.session_state.messages.append({"role": "user", "content": question})
    with st.chat_message("user"):
        st.write(question)

    answer = load_service()(question)
    st.session_state.messages.append({"role": "assistant", "content": answer})
    with st.chat_message("assistant"):
        st.write(answer)
```

실행합니다.

```bash
streamlit run app.py
```

## 코드에서 볼 부분

```python
@st.cache_resource
def load_service(): ...
```

모델이나 Vector Store를 매 재실행마다 다시 만들지 않게 합니다. 반면 사용자별 메시지는 `session_state`에 저장합니다.

## 배포 구성

```text
Git 저장소
├─ app.py
├─ requirements.txt
└─ .streamlit/config.toml  선택

API Key → 배포 환경의 Secrets에 저장
```

비밀값을 코드나 Git 저장소에 넣지 않습니다.

## 요점 정리

1. Streamlit은 사용자 동작마다 Python 스크립트를 다시 실행합니다.
2. 사용자별 대화는 `session_state`에 저장합니다.
3. 모델·DB 연결은 `cache_resource`로 재사용합니다.
4. UI 코드와 RAG·Agent 서비스 로직을 분리합니다.
5. API Key는 환경 변수나 배포 Secrets로 관리합니다.
