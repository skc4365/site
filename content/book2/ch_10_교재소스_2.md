## 검토 결과

기존 문서는 `main.py` 중심이라 `rag/base.py`, `rag/pdf.py`, `rag/evaluation.py`, `rag/utils.py`로 역할을 나눈 구조가 드러나지 않습니다. UI·RAG·평가·캐시를 분리하는 예제가 교육상 필요합니다.

## 권장 프로젝트 구조

```text
rag_app/
├─ main.py              # 화면과 사용자 이벤트
├─ rag/
│  ├─ base.py           # 공통 인터페이스
│  ├─ pdf.py            # PDF 로드·분할·검색 체인
│  ├─ evaluation.py     # 평가 데이터와 점수
│  └─ utils.py          # 공통 유틸리티
├─ data/                 # 허용된 업로드 파일
├─ .env.example
└─ requirements.txt
```

## 무거운 리소스 캐시

```python
import streamlit as st


@st.cache_resource(show_spinner="검색 인덱스를 준비하고 있습니다.")
def build_retriever(file_hash: str, file_path: str):
    documents = load_and_split_pdf(file_path)
    return create_vector_store(documents).as_retriever()
```

파일 이름만 캐시 키로 사용하면 내용이 바뀌어도 이전 결과가 재사용될 수 있으므로 파일 해시를 포함합니다.

## 세션 상태

```python
if "messages" not in st.session_state:
    st.session_state.messages = []

for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.markdown(message["content"])
```

## 배포 체크리스트

- API 키를 코드나 저장소에 넣지 않고 배포 환경의 Secrets로 관리합니다.
- 업로드 확장자·크기·저장 위치를 제한합니다.
- 임시 파일의 삭제 시점과 사용자별 격리를 정합니다.
- 인덱스 생성 실패와 모델 호출 실패를 사용자 메시지와 로그로 분리합니다.
- 답변에 출처를 표시하고 평가 결과는 개발·관리 화면에서만 노출합니다.
- 배포 후 헬스체크, 응답 시간, 오류율, 모델 비용을 관찰합니다.
