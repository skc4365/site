# Chapter 03 쉬운 제조 실습 — 가장 단순한 구조 고르기

## 쉬운 말

| 기술 용어 | 쉬운 표현 |
|---|---|
| 싱글 에이전트 | 도우미 한 명 |
| 멀티 에이전트 | 역할이 다른 도우미 여러 명 |
| Workflow | 미리 정한 작업 순서 |
| Supervisor | 진행 담당 도우미 |

## 후보 1: 도우미 한 명

```text
[사용자] → [기계 도우미]
               ├─ 숫자 확인
               ├─ 안내서 검색
               └─ 결과 설명
```

기능이 적고 모두 읽기 작업이면 이 구조가 가장 쉽습니다.

## 후보 2: 미리 정한 작업 순서

```text
질문 확인
 → 기계 이름 검사
 → 숫자 읽기
 → 안내서 검색
 → 확인 자료 검사
 → 답변
```

순서와 실패 처리가 중요하면 이 구조를 사용합니다. 교육 프로젝트의 기본 구조입니다.

## 후보 3: 역할이 다른 도우미

```text
                ┌→ [숫자 담당]
[진행 담당] ────┼→ [안내서 담당]
                └→ [보고서 담당]
```

각 역할의 데이터 권한이나 운영팀이 실제로 다를 때만 사용합니다.

## 선택 실습

각 질문에 예/아니요로 답합니다.

- 기능이 세 개 이하인가?
- 모든 기능이 같은 프로그램 안에서 실행되는가?
- 모든 기능이 읽기 전용인가?
- 한 팀이 전체 프로그램을 관리하는가?

대부분 “예”라면 도우미 한 명이나 미리 정한 작업 순서로 충분합니다.

## 구조 선택 기록

```markdown
# 우리가 선택한 구조

선택: 미리 정한 작업 순서

이유:
1. 숫자 확인과 안내서 검색 순서를 쉽게 볼 수 있다.
2. 오류가 생긴 위치를 찾기 쉽다.
3. 아직 여러 서버로 나눌 필요가 없다.
```

## 그림 설명 연습

다른 교육생에게 그림을 보여주고 다음을 설명합니다.

1. 사용자의 질문은 어디로 들어가는가?
2. 실제 숫자는 누가 읽는가?
3. 오류가 나면 어디에서 멈추는가?
4. 사람이 확인해야 하는 곳은 어디인가?

## 완료 기준

- [ ] 도우미 한 명과 여러 명의 차이를 설명했다.
- [ ] 복잡한 구조를 무조건 선택하지 않았다.
- [ ] 선택 이유를 세 문장으로 기록했다.
- [ ] 그림을 보고 작업 흐름을 설명할 수 있다.
