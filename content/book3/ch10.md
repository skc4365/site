# A2A로 에이전트 연결하기

## 먼저 보는 구조

```text
Agent A
  → Agent Card 확인
  → 작업 요청
  → 상태 확인
  ← 결과 수신
Agent B
```

> MCP가 Agent와 도구의 연결이라면, A2A는 독립된 Agent와 Agent의 연결입니다.

## Agent Card란?

Agent가 자신을 소개하는 정보입니다.

```json
{
  "name": "Greeting Agent",
  "url": "http://127.0.0.1:8010",
  "skills": [
    {"id": "greet", "name": "greet"}
  ]
}
```

호출자는 Card를 보고 주소와 제공 기능을 확인합니다.

## Try — 발견부터 결과까지

```python
import httpx

base_url = "http://127.0.0.1:8010"

card = httpx.get(
    f"{base_url}/.well-known/agent-card.json"
).json()
print("발견한 Agent:", card["name"])

response = httpx.post(
    f"{base_url}/tasks",
    json={"message": "코딩곰"},
)
print(response.json())
```

## MCP와 A2A 비교

| 구분 | MCP | A2A |
|---|---|---|
| 연결 | Agent ↔ 도구 | Agent ↔ Agent |
| 상대 | 기능 제공자 | 독립적인 작업 수행자 |
| 핵심 | Tool 발견과 호출 | 능력 발견과 작업 위임 |

## 바로 실행하는 심플 예제

A2A의 `Agent Card → Task → 결과` 흐름을 표준 Python만으로 확인하는 축소 예제입니다.

```python
from dataclasses import dataclass


@dataclass
class AgentCard:
    name: str
    skill: str


@dataclass
class Task:
    request: str
    status: str = "submitted"
    result: str = ""


def remote_agent(card: AgentCard, task: Task) -> Task:
    task.status = "working"
    task.result = f"{card.name}이 {card.skill} 작업을 완료했습니다: {task.request}"
    task.status = "completed"
    return task


card = AgentCard(name="Report Agent", skill="보고서 작성")
completed_task = remote_agent(card, Task(request="RAG 요약"))
print(completed_task.status)
print(completed_task.result)
```

실제 A2A에서는 이 구조를 네트워크 메시지와 표준 스키마로 교환합니다.

## 기억할 내용

1. Agent Card로 상대 Agent의 능력을 발견한다.
2. 작업에는 요청·상태·결과가 있다.
3. 서버별 주소와 시간 초과를 관리한다.
