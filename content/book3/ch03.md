# 싱글과 멀티 에이전트 선택하기

## 먼저 보는 구조

```text
싱글 Agent: 사용자 → 한 Agent → 도구들 → 답변

멀티 Agent : 사용자 → 조정자 → 전문 Agent A
                            └→ 전문 Agent B → 답변
```

> 역할이 많다고 바로 멀티 에이전트가 필요한 것은 아닙니다.

## 언제 무엇을 사용할까?

| 기준 | 싱글 Agent | 멀티 Agent |
|---|---|---|
| 역할 | 하나로 설명 가능 | 전문 역할이 분명히 나뉨 |
| 도구 | 적고 비슷함 | 역할별 도구와 권한이 다름 |
| 실행 | 단순하고 빠름 | 전달과 조정이 필요함 |
| 디버깅 | 비교적 쉬움 | 실패 위치가 늘어남 |

처음에는 싱글 Agent로 만들고, 책임이나 권한을 분리해야 할 때 멀티 Agent로 확장합니다.

## Try — 두 역할 연결하기

```python
def researcher(topic: str) -> list[str]:
    return [f"{topic}의 정의", f"{topic}의 장점", f"{topic}의 주의점"]


def writer(notes: list[str]) -> str:
    return " / ".join(notes)


research_result = researcher("멀티 에이전트")
final_answer = writer(research_result)
print(final_answer)
```

이 코드는 조사 역할의 결과를 작성 역할로 전달합니다. 멀티 Agent의 핵심도 **역할과 전달 데이터**를 명확히 하는 것입니다.

## 선택 질문

- 역할마다 사용하는 데이터가 다른가?
- 역할마다 권한을 다르게 줘야 하는가?
- 각 역할을 별도로 시험할 필요가 있는가?
- 조정 비용보다 분리 효과가 큰가?

대부분 “아니요”라면 싱글 Agent가 더 알맞습니다.

## 기억할 내용

1. 단순한 문제는 싱글 Agent부터 시작한다.
2. 멀티 Agent는 역할·권한·실패를 분리하기 위한 구조다.
3. Agent 사이에는 필요한 데이터만 전달한다.
