## 1. common

### `config.py`

Pydantic으로 Agent의 이름·URL·포트·설명을 정의합니다.

```python
from pydantic import BaseModel


class AgentConfig(BaseModel):
    name: str
    url: str
    port: int
    description: str
```

### `schemas.py`

A2A 요청·응답과 Agent 간 공유 데이터 schema를 정의합니다. 이 파일을 먼저 읽으면 서비스가 주고받는 데이터 형태를 파악할 수 있습니다.

### `a2a_client.py`

원격 Card 조회, A2AClient 생성, 메시지 전송을 공통 코드로 묶습니다.

## 2. orchestrator_agent

```text
agent.py           요청 분석·계획·원격 Agent 호출·결과 통합
agent_executor.py  A2A 요청을 Orchestrator에 연결
agent_server.py    Card·Handler·Server 구성
```

확인할 핵심:

- 사용자 요청에서 작업 목록을 어떻게 만드는가?
- 어떤 Agent Card를 보고 역할을 선택하는가?
- 원격 결과를 어떻게 합치는가?
- 일부 Agent 실패를 어떻게 표현하는가?

## 3. web_research_agent

```text

```

핵심 파일:

```text
web_research_agent/agent.py
web_research_agent/agent_executor.py
web_research_agent/agent_server.py
```

## 4. internal_rag_agent

구성 요소:

- LangGraph 기반 검색 흐름
- Supabase pgvector
- 문서 색인과 검색
- 검색 결과를 이용한 답변

핵심 파일:

```text
internal_rag_agent/agent.py
internal_rag_agent/index.sql
internal_rag_agent/test_index.py
internal_rag_agent/agent_executor.py
internal_rag_agent/agent_server.py
```

`index.sql`은 pgvector 검색에 필요한 DB 구조를 준비합니다. Python 코드보다 먼저 schema와 검색 함수를 확인합니다.

## 5. file_management_agent

구성 요소:

- Google Drive Client
- 파일 업로드·다운로드
- storage reference 관리
- AgentExecutor와 A2A Server

핵심 파일:

```text
file_management_agent/gdrive_client.py
file_management_agent/agent.py
file_management_agent/agent_executor.py
file_management_agent/agent_server.py
```

Google OAuth 자격증명과 API 권한이 필요하므로 다른 Agent와 분리해 실행합니다.

## Python 3.12·LangChain 1.x 확인점

- Python 3.12 가상환경 하나에서 lock 파일 기준으로 먼저 재현합니다.
- LangChain·LangGraph 1.0 계열 API와 A2A SDK 버전을 함께 고정합니다.
- 네 Agent 서버의 working directory와 import 경로를 확인합니다.
- Card URL·포트·실제 서버 주소가 일치해야 합니다.
- Supabase·Google Drive·Tavily를 한 번에 디버깅하지 말고 Agent별로 확인합니다.
- `test_client.py` 이전에 각 Agent를 독립 테스트합니다.
