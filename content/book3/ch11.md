# 최종 멀티 에이전트 구조 완성하기

## 먼저 보는 구조

```text
사용자
  ↓
Orchestrator
  ├→ Research Agent
  ├→ Review Agent
  └→ Writer Agent
  ↓
최종 답변 + 실행 기록
```

> 최종 프로젝트의 핵심은 기능의 개수가 아니라, 역할·데이터·실패 경계가 보이는 구조입니다.

## 지금까지 연결하기

| 배운 내용 | 최종 구조에서의 위치 |
|---|---|
| 도구 | 각 Agent가 사용하는 기능 |
| LangGraph | 작업 순서와 분기 |
| 싱글 Agent | 하나의 전문 역할 |
| 멀티 Agent | 역할 분리와 조정 |
| 메모리 | 대화와 필요한 정보 유지 |
| MCP | 외부 도구 연결 |
| A2A | 독립 Agent 연결 |

## Try — 세 역할의 데이터 흐름

```python
def research(request: str) -> dict:
    return {"request": request, "facts": ["핵심 사실 1", "핵심 사실 2"]}


def review(state: dict) -> dict:
    state["review"] = "근거와 표현을 확인했습니다."
    return state


def write(state: dict) -> str:
    facts = ", ".join(state["facts"])
    return f"{facts}\n검토: {state['review']}"


state = research("AI 에이전트 학습 순서")
state = review(state)
print(write(state))
```

각 역할은 앞 단계의 결과를 받아 자신의 결과를 추가합니다. LangGraph에서는 이 데이터가 State입니다.

## 완성 전에 확인하기

- 각 Agent를 따로 시험할 수 있는가?
- 입력과 출력 구조가 정해져 있는가?
- 실패한 역할과 이유를 찾을 수 있는가?
- 재시도와 종료 조건이 있는가?
- API 키와 민감 정보가 로그에 남지 않는가?

## 기억할 내용

1. Orchestrator는 역할과 순서를 조정한다.
2. State는 역할 사이의 계약이다.
3. 작은 실행 흐름을 확인한 뒤 기능을 확장한다.
