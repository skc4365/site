# MCP로 외부 도구 연결하기

## 먼저 보는 구조

```text
Agent(MCP Client)
       ↓ 도구 목록 조회·호출
MCP Server
       ↓
검색·파일·데이터 기능
```

> MCP는 Agent와 외부 도구가 같은 방식으로 대화하도록 만든 연결 규칙입니다.

## 역할 구분

| 구성요소 | 하는 일 |
|---|---|
| MCP Server | Tool·Resource·Prompt 제공 |
| MCP Client | 서버에 연결하고 기능 조회 |
| Agent | 어떤 Tool을 사용할지 판단 |

## Try — 가장 작은 MCP Tool

서버:

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("lesson-tools")


@mcp.tool()
def add(left: int, right: int) -> int:
    """두 정수를 더합니다."""
    return left + right


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

`stdio` 방식에서는 Client가 서버 프로세스를 실행하고 표준 입출력으로 통신합니다.

## 실행 순서

```text
Client 시작
  → Server 프로세스 시작
  → initialize
  → list_tools
  → call_tool("add")
  → 결과 42
```

## 주의할 점

- stdio 서버에서 일반 `print()`로 프로토콜을 방해하지 않습니다.
- Client와 Server가 같은 Python 환경을 사용하게 합니다.
- Tool 입력과 파일 경로를 검증합니다.
- 연결 실패와 시간 초과를 처리합니다.

## 바로 실행하는 심플 예제

아래 코드는 `add` 도구 하나를 제공하는 최소 MCP Server입니다.

```bash
pip install -U "mcp[cli]"
```

```python
from mcp.server.fastmcp import FastMCP


mcp = FastMCP("calculator")


@mcp.tool()
def add(a: int, b: int) -> int:
    """두 정수를 더합니다."""
    return a + b


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

코드를 `server.py`로 저장하고 `python server.py`를 실행하면 Server가 표준 입출력으로 Client 연결을 기다립니다.

## 기억할 내용

1. MCP Server는 도구를 제공한다.
2. MCP Client는 도구를 발견하고 호출한다.
3. Agent는 도구 선택을 담당한다.

## 원리와 아키텍처 학습 링크

- [MCP architecture](https://modelcontextprotocol.io/docs/learn/architecture) — Host, Client, Server와 Transport가 분리된 프로토콜 구조를 학습합니다.
- [MCP specification](https://modelcontextprotocol.io/specification/latest) — 초기화, Capability 협상, Tool 발견·호출 메시지의 공식 계약을 확인합니다.
- [LangChain MCP adapters](https://docs.langchain.com/oss/python/langchain/mcp) — 여러 MCP Server의 도구를 LangChain Agent에 연결하는 실행 흐름을 봅니다.
