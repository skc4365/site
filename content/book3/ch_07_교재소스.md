## 1. Command 기초

`how_to_use_command.ipynb`는 `Command`를 이용해 상태 갱신과 이동을 한 번에 반환하는 방법을 다룹니다.

```python
from langgraph.types import Command

return Command(
    update={"messages": new_messages},
    goto="next_agent",
)
```

## 2. network_agent

`make_graph.py`는 두 역할을 등록합니다.

```python
from langgraph.graph import MessagesState, START, StateGraph

builder = StateGraph(MessagesState)
builder.add_node("researcher", research_node)
builder.add_node("html_generator", html_node)
builder.add_edge(START, "researcher")

graph = builder.compile()
```

`research_agent.py`는 검색 결과에 따라 HTML 역할 또는 END로 이동합니다.

```python
def research_node(
    state: MessagesState,
) -> Command[Literal["html_generator", END]]:
    result = research_agent.invoke(state)
    last_message = result["messages"][-1]
    goto = END if "최종 답변" in last_message.content else "html_generator"
    return Command(update={"messages": result["messages"]}, goto=goto)
```

`chart_agent.py`는 HTML 파일 생성 도구를 사용하고 다시 researcher 또는 END로 이동합니다.

## 3. supervisor_agent_triple

세 전문 역할:

```python
agents = {
    "web_search": create_web_agent,
    "db_search": create_db_search_agent,
    "faq": create_faq_agent,
}
```

Supervisor는 각 역할로 넘기는 handoff 도구를 사용합니다.

```python
supervisor = create_agent(
    model=model,
    tools=handoff_tools,
    system_prompt=get_system_prompt(),
)
```

Graph는 모든 전문 역할을 다시 supervisor에 연결합니다.

```text
supervisor → web_search ─┐
           → db_search  ─┼→ supervisor
           → faq        ─┘
```

## 4. 병렬 handoff

`handoff_tools.py`는 한 AIMessage에 여러 tool call이 있으면 각 작업을 `Send`로 만듭니다.

```python
from langgraph.types import Command, Send

send_list.append(
    Send(
        target_agent,
        {**state, "messages": agent_messages, "query": query_content},
    )
)

return Command(graph=Command.PARENT, goto=send_list)
```

각 병렬 작업에는 해당 tool call만 포함한 AIMessage와 대응 ToolMessage가 필요합니다.

## Python 3.12·LangChain 1.x 확인점

- Agent 생성은 `langchain.agents.create_agent`를 사용합니다.
- 이동 명령은 `langgraph.types.Command`, 병렬 작업은 `Send`입니다.
- 여러 tool call의 ToolMessage는 각각 고유한 `tool_call_id`와 대응되어야 합니다.
- 메시지 본문 문자열로 종료 여부를 판정하는 예제는 학습용입니다. 실제 구현에서는 구조화된 상태가 더 안전합니다.
- 역할 간 순환에는 최대 이동 횟수와 종료 조건이 필요합니다.
